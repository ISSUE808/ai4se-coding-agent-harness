# CodeHarness WebUI — 设计需求文档（Design Brief）

> 本文档是 Open Design AI 设计三页 UI（Dashboard / SessionDetail / Settings）的需求输入。
> **布局与视觉风格完全由你自由发挥**——本文档只定义三件事：产品是什么、每页必须包含什么、最终必须导出什么格式的 token 文件。除此之外都是你的设计空间。

---

## 1. 产品背景

**CodeHarness** 是一个 AI 编码智能体（Coding Agent）运行框架：用户给 agent 一个编程任务，agent 自主完成「思考 → 调工具（读文件/写文件/跑测试/执行命令）→ 反馈验证 → 修正」的循环，直到任务完成。

WebUI 是这个 agent 的**实时驾驶舱**：用户创建会话、观察 agent 执行过程、在关键命令需要人工确认（HITL）时审批、管理 API Key 与配置。

技术背景（影响设计的信息密度与实时性预期）：
- 前端：React + TypeScript + shadcn/ui（Tailwind），Monaco Editor 用于代码 diff 与 JSON 编辑
- 后端：Express REST + **WebSocket 事件实时推送**（消息/工具执行/反馈结果/护栏触发/状态变化，延迟 ≤100ms）——消息流是持续流动的
- 用户：开发者，桌面 Web 应用（最小宽度 ~1024px）

---

## 2. 设计目标

1. **实时感**：消息流像流水一样更新，用户扫一眼就知道"正在发生什么"
2. **高信息密度但可扫描**：状态、轮次、token 数、反馈结果一眼可读
3. **状态清晰**：反馈通过/失败、护栏拦截、待人工审批等"机器做决定"的时刻必须视觉明确
4. **专业开发者工具审美**：紧凑、克制、功能优先

---

## 3. 视觉方向（建议，可自由探索）

- **暗色主题**（开发者工具惯例），低饱和，状态色仅用于"状态"
- 参考质感：Linear / Vercel Dashboard / GitHub Actions
- UI 文本用无衬线字体；**命令、代码、ID、token 数用等宽字体**——代码气质是产品的核心气质

---

## 4. 页面：目的 + 必须包含的元素

### 4.1 Dashboard
**目的**：一眼看到所有会话及其状态，启动新会话。
- 活跃会话列表，每项至少展示：会话 ID、任务描述、状态（running / paused / completed / failed）、当前轮次/最大轮次、运行时长、token 数
- "新建会话"入口（明显的主操作）
- 空状态引导

### 4.2 SessionDetail（核心页面，三栏布局）
**目的**：实时观察单个 agent 会话，并在必要时人工介入。
- **三栏**：左＝文件变更 / 中＝消息流 / 右＝上下文信息
- **文件变更栏**：agent 修改过的文件列表（新增/修改/删除标记），点击可预览 diff
- **消息流栏**（主体，实时更新，自动滚动）：
  - 消息按角色区分：user / assistant / tool / feedback / system
  - **Tool 调用卡片**：默认折叠（工具名+状态），可展开看参数与结果；失败的红色标识
  - **反馈结果**：绿（通过）/ 红（失败）明确标记，失败可展开看证据
  - **HITL 审批卡**：内联显示待审命令 + 批准 / 编辑（可修改命令后提交）/ 拒绝 三操作
  - 底部消息输入框
- **上下文信息栏**：状态、轮次进度、token 数、时间、文件数等
- **页面头**：返回入口、会话标题、状态、暂停/恢复、停止（危险操作）

### 4.3 Settings
**目的**：管理 API Key + 编辑配置。
- **Key 管理**：provider 列表——名称、掩码值（`****-后4位`）、更新（隐藏输入）、删除（带确认）
- **配置编辑**：Monaco JSON 编辑器 + 保存 + 校验错误提示

## 5. 组件清单（类型由产品决定，视觉由你决定）

Button（主/次/危险）、状态 Badge、Card、列表行、消息气泡、可展开 Tool 卡片、审批卡、文件项（含 diff）、进度条、输入框、空状态。如需拆解或补充组件，由你判断。

---

## 6. Design Token 导出契约（**硬性要求，务必遵守**）

导出为一个 **TypeScript 文件**：`src/webui/client/src/design-tokens.ts`（`export const designTokens = {...}; export default designTokens;`）。前端 React 代码直接 import 它，**任何 UI 不得硬编码颜色/字号/间距**。

结构与命名规则：
1. 对象键按类别组织：`colors` / `spacing` / `typography` / `radius` / `shadows`
2. **颜色一律语义命名**（`primary`、`success`、`danger`、`warning`、`info`、`bg`、`surface`、`border`、`text`、`textMuted`、`codeBg` 等），**禁止裸色名**（如 `green`/`red`）——这是前端代码引用的契约，无法妥协
3. 间距为刻度制（如 4/8/12/16/24/32 或你的方案）；字号含 UI 与等宽两套；圆角与阴影至少 2 级
4. 每个状态（hover/active/disabled）与每个组件的颜色都应有对应 token——覆盖你设计的全部 UI
5. 色值由你从零设计一套协调的暗色配色，本文件不指定任何具体数值

---

## 7. 边界（本轮不做）

- 不做亮色主题（token 结构预留扩展即可）
- 不做复杂动效/动画（最多悬停/展开/状态脉冲）
- 不做移动端适配
- 不做品牌营销视觉——这是开发者工具
